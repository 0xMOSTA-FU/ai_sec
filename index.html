STEP 1 Web Sec Basics & API Hacking

Before hacking AI, you must understand the wrappers around it. LLMs are interacted with via APIs and web interfaces. Mastery of OWASP Top 10 for Web and API security is non-negotiable.

  • HTTP protocols, REST/GraphQL endpoints, and WebSocket manipulation.
  • Burp Suite / Postman mastery for intercepting LLM context payloads.

STEP 2 LLM Architecture (Transformers, RAG)

Understand the brain. You must know how tokens are processed, how the context window limits function, and the architecture of Retrieval-Augmented Generation (RAG) involving Vector Databases (like Pinecone, Milvus).

STEP 3 Prompt Injection & Jailbreaking

The core of AI Red Teaming. Crafting adversarial inputs to bypass safety filters (Guardrails). Learning Direct Injection (DAN, Roleplay) vs Indirect Injection (Poisoning webpages the AI reads).

STEP 4 RAG Exploitation & Data Poisoning

Exploiting the vector database. Injecting malicious documents into the knowledge base so that when the RAG system retrieves data, it fetches and executes your payload (Secondary Prompt Injection).

STEP 5 MITRE ATLAS TTPs

Formalizing the attack structure. Mapping your attacks to the Adversarial Threat Landscape for AI Systems (ATLAS). Understanding ML Model Evasion, Model Inversion, and Exfiltration techniques.

STEP 6 Hands-on HTB/Portswigger LLM Labs

Executing attacks in real environments. Pwning HackTheBox AI machines and completing the PortSwigger Web Security Academy LLM attack modules to solidify practical skills.

STEP 1 Python, KQL, SPL Scripting

Automation starts with code. Mastery of Python for scripting API calls, Kusto Query Language (KQL) for MS Sentinel, and Search Processing Language (SPL) for Splunk.

STEP 2 Splunk / MS Sentinel API Integrations

Connecting external AI logic to your SIEM. Writing scripts that pull alerts, push them to an LLM via API for analysis, and return the verdict to the SIEM dashboard.

STEP 3 Implementing AI Copilots in SOAR (n8n, Tines)

Building visual automation workflows. Using tools like Tines, n8n, or Cortex XSOAR to create playbooks where an AI Agent handles initial alert triage and contextual enrichment.

STEP 4 ML for UEBA & Anomaly Detection

Deploying statistical and ML models (e.g., Isolation Forests, Autoencoders) to establish baseline behaviors and detect deviations indicative of insider threats or compromised credentials.

STEP 5 Automated Threat Intelligence Parsing

Using LLMs to scrape unstructured data (PDF reports, Twitter/X feeds, dark web forums) and extract structured Indicators of Compromise (IoCs) to feed back into firewalls/SIEMs instantly.

STEP 1 Secure Model Pipelines

Securing the CI/CD pipeline for Machine Learning (MLOps). Ensuring that training data lakes are encrypted, access is restricted (IAM), and the infrastructure (Kubernetes/Docker) running the models is hardened.

STEP 2 HuggingFace Model Scanning & SafeTensors

Preventing Supply Chain Attacks. Moving away from insecure Python Pickle files which can execute arbitrary code upon load, and enforcing the use of `safetensors`. Scanning third-party models for embedded malware.

STEP 3 Defending AI APIs

The API is the front door. Implementing strict rate limiting to prevent Denial of Wallet (DoW) attacks on expensive LLM calls, implementing robust input sanitization, and setting context length limits.

STEP 4 Deploying NeMo Guardrails / Llama-Guard

Active defense mechanisms. Integrating specialized programmable frameworks (like NVIDIA NeMo) to intercept prompts before they hit the core LLM, rejecting policy-violating queries, and filtering the output for sensitive data leaks.

STEP 1 NIST AI RMF

Mastering the National Institute of Standards and Technology (NIST) AI Risk Management Framework. Understanding the core functions: Govern, Map, Measure, and Manage applied to AI lifecycles.

STEP 1 Secure AI Application Architecture

Understand trust boundaries between users, prompts, models, retrieval systems, plugins, tools, and application permissions.

STEP 2 Agent & Tool Authorization

Secure function calling, tool permissions, approval gates, least privilege, sandboxing, SSRF protection, and human-in-the-loop workflows.

STEP 3 AI AppSec Testing

Combine secure code review, API testing, threat modeling, prompt-injection testing, output validation, and abuse-case regression tests.

STEP 1 ML Foundations & Threat Models

Learn datasets, features, training, inference, classification, embeddings, and how attacker goals differ across ML systems.

STEP 2 Evasion, Poisoning & Extraction

Practice authorized experiments involving adversarial examples, data poisoning, model extraction, inversion, membership inference, and abuse of confidence scores.

STEP 3 Robustness Evaluation

Measure attack success, false positives, model drift, and mitigation effectiveness with reproducible benchmarks and documented limitations.

STEP 1 Data Discovery & Classification

Map training data, prompts, outputs, telemetry, vector stores, and third-party providers. Identify PII, secrets, regulated, and sensitive data.

STEP 2 Privacy-Preserving AI Controls

Implement minimization, retention limits, redaction, DLP, access controls, encryption, tenant isolation, and provider data-use controls.

STEP 3 Privacy Testing & Incident Response

Test memorization, prompt leakage, membership inference, and accidental disclosure, then document notification and containment procedures.

STEP 1 Read & Reproduce Research

Follow peer-reviewed papers, security advisories, benchmark releases, and reproduce results in isolated environments.

STEP 2 Design Responsible Experiments

Define scope, ethics, safety boundaries, baselines, metrics, and reproducibility before testing a new attack or defense.

STEP 3 Publish Findings & Build Tools

Turn results into a clear technical report, reproducible code, defensive recommendations, and coordinated disclosure where appropriate.

STEP 2 OWASP LLM Top 10

Translating technical vulnerabilities into risk metrics for leadership. Building enterprise policies that mandate testing against the OWASP LLM Top 10 before deploying any generative AI applications.

STEP 3 IAPP AIGP Certification

Acquiring the Artificial Intelligence Governance Professional certification. The gold standard for understanding the intersection of AI functionality and global privacy laws.

STEP 4 EU AI Act Compliance

Understanding regulatory compliance. Classifying AI systems into risk categories (Unacceptable, High, Limited, Minimal) and ensuring enterprise development aligns with the strict requirements of the European Union AI Act.

How to choose

Prefer offensive work? Start with AI Red Teaming and AppSec. Prefer engineering? Choose MLSecOps, platform security, or guardrails. Prefer policy and communication? Choose AI GRC, model risk, or privacy engineering.

System lifecycle map

01 · Data

Collect & prepare

Provenance, consent, secrets, poisoning, PII, labeling, retention, and dataset access.

Evidence: dataset card, lineage, access review, poisoning checks.

02 · Build

Train & integrate

Dependencies, model artifacts, prompts, plugins, retrieval indexes, CI/CD, and secrets.

Evidence: SBOM, model provenance, signed artifacts, threat model.

03 · Evaluate

Measure before release

Capability, misuse, privacy, robustness, jailbreak, prompt injection, and agent boundary tests.

Evidence: eval set, attack results, severity rubric, release gate.

04 · Deploy

Expose safely

Identity, authorization, rate limits, sandboxing, output validation, network egress, and tenant isolation.

Evidence: architecture diagram, policy tests, rollback plan.

05 · Operate

Monitor & respond

Telemetry, abuse detection, drift, anomalous tool calls, data leakage, incident triage, and forensics.

Evidence: dashboards, alerts, incident runbooks, postmortems.

06 · Retire

Decommission responsibly

Revoke access, archive decisions, remove secrets, destroy temporary data, and preserve audit evidence.

Evidence: retirement checklist, access revocation, retention record.

Role-based playbooks

For SOC & blue teams

  1. Normalize AI telemetry with identity, tool, retrieval, and output context.
  2. Create detections for abnormal prompts, data access, tool chains, and token spend.
  3. Use a human approval gate for destructive or high-impact actions.
  4. Preserve prompts, retrieved sources, tool calls, and model versions for investigations.
Build with Wazuh

For pentesters & red teams

  1. Define authorization, scope, test data, rate limits, and stop conditions.
  2. Map the attack surface: model, prompt, RAG, tools, identity, APIs, and integrations.
  3. Run reproducible probes and manually validate impact, not just model refusal.
  4. Report exploit path, business impact, evidence, remediation, and regression test.
Use PortSwigger labs

For GRC & risk teams

  1. Inventory AI systems, owners, vendors, data, users, and decisions.
  2. Classify impact and map controls to NIST AI RMF, ISO/IEC 42001, and applicable law.
  3. Require evidence for evaluation, monitoring, human oversight, incidents, and third parties.
  4. Track residual risk, exceptions, control owners, review dates, and sign-off.
Map to NIST AI RMF

For AI engineers

  1. Threat-model every trust boundary before adding retrieval or tool use.
  2. Make least privilege, validation, sandboxing, and safe failure part of the architecture.
  3. Ship security evaluations as CI gates with versioned datasets and thresholds.
  4. Instrument runtime behavior and make rollback possible.
